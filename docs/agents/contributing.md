# Agent contribution workflow

Read [CONTRIBUTING](../../CONTRIBUTING.md) before editing or reviewing. It is the shared source for offline setup, checks, source-pin updates, and evidence expectations.

1. Inspect the worktree and applicable instructions. Identify the issue or approved behavior, intended write set, acceptance example, and validation command. Preserve unrelated changes and resolve overlapping ownership before writing.
2. Distinguish proposed requirements from accepted contracts. Read the relevant contract documents linked from the contributor guide. Surface conflicts before changing terminology or behavior; a proposal or ticket claim does not grant implementation or live-operation authority.
3. Implement and validate only the assigned scope using the guide's test-first and source-pin procedures. Keep observed checks distinct from inferred behavior; fixtures do not qualify a live provider.
4. Hand off changed files, exact commands/results, requirement and decision links, and unresolved limitations. Preserve substantive contract and test evidence in the issue or an established repository artifact. Full private reasoning or agent transcripts are unnecessary.

If an assignment explicitly requires separate test and implementation authors, preserve that separation and the accepted test snapshot. Return contradictions to the driver for a decision. Report any inability to meet the assignment instead of silently claiming compliance. This supplement does not prescribe a model, paid tool, personal skill installation, or a separate-author requirement for every contribution.
