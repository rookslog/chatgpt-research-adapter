## API

New src/standard-runtime.js exports initializeStandardRuntime({root,capacity=4}), inspectStandardRuntime({runtime,operationRef,requestKey}), dispatchNextStandard({runtime,context,driver}), recordStandardObservation({runtime,operationRef,expectedRevision,observation,context}). Existing submitPreparedJobOnce accepts optional runtime:{root,epoch}, requestKey, context. Without runtime it keeps existing refusal. Runtime initializes explicitly; no automatic replacement after loss.

initialize returns {runtime_epoch,capacity}; root may be nonexistent but its parent must exist. Existing/nonempty root refuses reinitialization. Runtime descriptor epoch must match. Admission receipt has admission accepted|existing, runtime_epoch, job_ref, operation_ref, revision, phase, submission_effect, attention. Inspect returns runtime_epoch,revision,capacity,occupied,operations; operation entries include operation_ref,job_ref,revision,phase,submission_effect,priority,arrival_sequence,intent,binding,attention. Phase queued/dispatching/observing/collecting/settled. submission_effect known_unsent/unknown/accepted. Source jobId is distinct from stable runtime job_ref and operation_ref.

Context is an internal trusted integration object, not serialized user testimony: optional priority normal|high|background (default normal), authorize(operation) => boolean (default allow only normal initial local operation), deliveryReady(operation) => boolean (default false), clock:{now:()=>milliseconds,sleep:async(ms)=>void} (default real monotonic elapsed implementation), random:()=>number in[0,1) (default platform randomness). Callback exceptions hold/refuse, not permission. Declared operation kind is initial only; no caller hierarchy. Output roots/file access remain real OS permissions. Fake context only proves core semantics, not real active delivery or arbitrary delegated permission enforcement.

Admission loads real prepared v2 through existing validator and captures exact prompt/model/effort and source destination into immutable intent. requestKey is1–128 printable ASCII characters, no control characters. Same key and identical prepared identity/immutable contents returns original current operation; conflict returns ERR_RUNTIME_REQUEST_KEY_CONFLICT. No new transport calls at admission. Max256 operations, max1MiB prompt, max16MiB snapshot; no eviction. Runtime accepts local filesystem same-host cooperating processes only. capacity is integer1–4. Error codes use ERR_RUNTIME_*; tests should check documented typed cases rather than every internal wording.

## Integrity and dispatch

One atomic versioned runtime-state.json snapshot contains epoch,key map,intents,operations,reservations,pacing. Sync temporary snapshot, rename and parent directory; acceptance only after success. Root and files must be regular owned directory/file identities, no symlink/replacement traversal. Missing/corrupt/untrusted state or wrong epoch refuses via ERR_RUNTIME_HISTORY_UNAVAILABLE or ERR_RUNTIME_EPOCH. Whole-store rollback cannot be detected from that store alone; do not claim it. Refuse unsupported sync durability, no automatic deletion/retention.

Separate state mutex and effect mutex. Non-expiring ownership, no timed takeover. State mutex only around short mutations; admission and inspection remain possible during asynchronous provider work. Concurrent live contenders can return typed ERR_RUNTIME_BUSY and bounded caller retry may be used for known-unsent local operations. No retry of provider send. Abandoned/untrustworthy owner yields ERR_RUNTIME_OWNER_UNRESOLVED; opaque handles/filesystem identity prevent deleting/reusing a successor's owner. No public remove-lock API. Tests may simulate disappearance/replacement of owned lock files only if verifying conservative refusal; no auto repair implied.

Order eligible initial requests by priority high/normal/background then arrival FIFO. Held preferred work does not block eligible lower work. driver.prepare(operation) returns {status:ready,target,evidenceRef} or {status:held,reason}; it cannot send. driver.send(operation,preparedTarget) returns {status:accepted,binding:{conversationId,userMessageId},evidenceRef}. Required operation-specific delivery gate and authority must pass before any send. Hold does not reserve capacity.

Under effect mutex, recheck current state and capacity, wait a fresh monotonic4000+floor(random()*1001)ms quiet period before each attempted send, respect stored cooldown_until, durably reserve a slot and dispatch token with phase dispatching/effect unknown BEFORE send callback. Shared mutex prevents two workers taking fourth slot or overlapping sends. Exception/malformed acceptance/missingbinding retains unknown and occupancy; do not accept an arbitrary known-unsent assertion after send. Qualified acceptance sets observing/accepted with immutable binding. dispatchNext returns status dispatched|idle|held,operation_ref nullable,reason nullable,snapshot nullable. Unknown is not eligible for another send.

recordStandardObservation uses expected per-operation revision. observation:{status:running|completed|failed,conversationId,userMessageId,evidenceRef}. Exact binding required; wrong binding rejects ERR_RUNTIME_BINDING. Revision conflict ERR_RUNTIME_REVISION_CONFLICT. completed/failed releases slot, leaves effect accepted; completed moves collecting, failed settled with attention. This does not collect reports. Unknown-effect operations cannot be freed by fabricated completion. No followup/intervention admission in C1.
